# Assinaturas

# 💳 11 — ASSINATURAS

## 📌 Objetivo

O módulo de Assinaturas tem como objetivo permitir que o BusinessOS seja comercializado como um SaaS (Software as a Service), onde cada empresa paga uma assinatura recorrente para utilizar a plataforma.

Todo o processo de contratação, pagamento, renovação e cancelamento deverá ser automatizado, exigindo o mínimo de gerenciamento manual possível.

---

# 🎯 Problema

Gerenciar assinaturas manualmente gera diversos problemas:

- Cobranças esquecidas;
- Controle financeiro desorganizado;
- Clientes utilizando a plataforma sem pagar;
- Dificuldade para acompanhar inadimplência;
- Perda de escalabilidade.

---

# ✅ Solução

O BusinessOS possuirá um sistema próprio de assinaturas integrado ao Mercado Pago.

A plataforma deverá:

- Permitir contratação de planos;
- Gerenciar pagamentos;
- Controlar vencimentos;
- Aplicar períodos de teste;
- Bloquear contas inadimplentes;
- Liberar acesso automaticamente após pagamento.

# 🎁 Período de Teste (Trial)

Objetivo:

Permitir que o usuário conheça o sistema antes de contratar.

Exemplo:

Teste gratuito de 7 dias.

Durante o trial:

- Todos os recursos liberados;
- Sem cobrança;
- Sem necessidade de cartão.

Após o término:

- Solicitar assinatura;
- Bloquear acesso caso não assine.

- Pix

---

# 🔄 Renovação

As assinaturas deverão ser renovadas automaticamente.

Após confirmação do pagamento:

- Renovar período;
- Atualizar vencimento;
- Manter acesso.

---

# ❌ Cancelamento

O cliente poderá cancelar sua assinatura.

Após cancelamento:

- A assinatura permanece ativa até o final do período já pago;
- Não realizar novas cobranças;
- Possibilidade de reativação.

---

# ⚠️ Inadimplência

Quando o pagamento falhar:

Status:

Pagamento Pendente.

O sistema deverá:

1. Notificar o usuário;
2. Permitir regularização;
3. Aplicar período de tolerância.

Exemplo:

5 dias de tolerância.

Após esse período:

- Bloquear acesso;
- Manter dados armazenados;
- Permitir reativação após pagamento.

# ⬆️ Upgrade de Plano

O cliente poderá:

Starter → Pro

Pro → Premium

O sistema deverá:

- Atualizar permissões;
- Atualizar recursos disponíveis;
- Ajustar cobrança.

---

# ⬇️ Downgrade de Plano

Premium → Pro

Pro → Starter

Ao reduzir plano:

- Recursos premium ficam indisponíveis;
- Dados permanecem armazenados;
- Recursos voltam a funcionar caso o plano seja reativado.

---

# 🏢 Funcionamento Multi-Tenant

Cada empresa possui:

- Assinatura própria;
- Plano próprio;
- Histórico próprio.

Uma empresa nunca poderá visualizar informações de assinatura de outra.

---

# 🔒 Segurança

Somente usuários autorizados poderão:

- Visualizar assinatura;
- Alterar plano;
- Cancelar assinatura;
- Atualizar pagamento.

Integrações de pagamento devem ser feitas no servidor.

Nunca confiar no Front-End.

# 📐 Regras de Negócio

RN-01:

Toda empresa deve possuir uma assinatura.

RN-02:

Uma empresa pode ter apenas uma assinatura ativa.

RN-03:

Uma assinatura pertence a apenas uma empresa.

RN-04:

Pagamentos aprovados devem liberar acesso automaticamente.

RN-05:

Contas inadimplentes devem ser bloqueadas após o período de tolerância.

RN-06:

Cancelar assinatura não apaga os dados da empresa.

RN-07:

Todos os eventos de pagamento devem ser registrados.
